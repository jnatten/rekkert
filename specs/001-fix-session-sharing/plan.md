# Implementation Plan: Reliable Session Sharing, and Sharing from the Wrist

**Branch**: `001-fix-session-sharing` | **Date**: 2026-10-27 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-fix-session-sharing/spec.md`

## Summary

Guests fell off a match shared over Bluetooth while the host's own phone and watch carried
on. Reading the code found four independent ways that happens, each verified in the code:

- **The host's app is ended, and sharing never comes back.** The code lives only in memory,
  and Bluetooth has no state restoration (RC-1).
- **The host silently writes off a guest that is only following.** It stops sending to it,
  and the guest never notices (RC-2).
- **The host serves its guests in a fixed order.** Late guests starve once the transmit queue
  fills (RC-3).
- **The outbox can only be acknowledged if every guest answers within 4 s.** Past a certain
  size it is never acknowledged, it is resent whole to everyone, and lag snowballs (RC-4).

On the watch side:

- **A phone cannot wake its watch app** (RW-1).
- **The joined match can lose to the watch's own session.** A clock comparison runs before
  the watch learns its phone is a guest (RW-2).

The approach:

- **Keep the code and bring sharing back.** Keep the code, with its share id, in this-device
  Keychain on every device that has been on the match, for at most 12 hours. Bring sharing
  back on every launch, and add CoreBluetooth state restoration.
- **Fix how the host serves guests.** Take turns fairly, send each guest only what it is
  missing, and keep liveness running both ways. Count participants rather than links, so the
  host knows who is on and in what state, and turn away an eighth guest with "no room".
- **Fix the guest's watch.** Send the role with the snapshot, so a guest phone's match always
  wins on its watch. A notification brings the watch to the front, and the watch offers one
  tap to get on its phone's match.
- **Give the host's watch the controls.** It gets start, stop, the code (digits plus a QR
  image drawn on the phone) and the guest list, all over the existing `.sharing` channel.
- **Record what happens to the links.** A sharing record on each phone and watch, merged and
  shared from the phone.
- **Make it testable without devices.** Pull the Bluetooth state machine out behind a
  `Radio` protocol so it runs under `swift test`. Every root cause becomes a failing
  simulated-link test first.

The evidence and the alternatives are in [research.md](research.md).

## Technical Context

**Language/Version**: Swift 6.2 tools, Swift 6 language mode. Default isolation is
`MainActor` in the apps and in `RekkertSync`; `RekkertCore` is nonisolated.

**Primary Dependencies**: Apple frameworks only:

- SwiftUI and WatchKit;
- CoreBluetooth and Network.framework;
- WatchConnectivity;
- CryptoKit, and Security (Keychain);
- UserNotifications;
- Core Image, phone only, for the QR image;
- HealthKit (existing).

**Storage**:

- JSON files in the app container, via `SessionStore`: `active.json`, history and farewells.
- New: one Keychain item for the kept code.
- New: per-day sharing-record files in Application Support, excluded from backup.

**Testing**:

- Swift Testing via `swift test --package-path Packages/RekkertKit`, on macOS with no
  device. The new `SimulatedRadio` and the multi-device harness live there.
- `scripts/verify.sh` is the gate.
- `scripts/share.sh` runs the local-network path on simulators.
- One real-device field test before release, per [quickstart.md](quickstart.md).

**Target Platform**: iOS 26 (iPhone; the iPad target builds too) and watchOS 26.

**Project Type**: Mobile app for iPhone and Apple Watch, generated by Tuist, over a shared
Swift package (`Packages/RekkertKit`).

**Performance Goals** (from the spec):

- Points reach every in-range device: 95% within 5 s, all within 30 s (FR-002).
- The host sees a guest's state change within 15 s (FR-010).
- A device is back in step within 30 s of returning, or of the host's app running again
  (SC-003, SC-010).
- No stale score is shown as current for more than 15 s (SC-004).

**Constraints**:

- No Wi-Fi. Bluetooth LE carries a few kilobytes a second, through one transmit queue the
  host shares between its guests.
- WatchConnectivity refuses messages over 64 KB.
- iOS suspends backgrounded apps and may end them.
- watchOS cannot advertise, and a phone cannot wake its watch app.
- The code is a 20-bit secret and may not leave the devices that have been on the match.

**Scale/Scope**:

- A host and up to seven guests, each with a phone and a watch: up to 16 devices over two
  neighbouring courts.
- Evenings of up to 12 hours; logs as large as an americano evening's.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle | Gate | Pre-research | Post-design |
|---|---|---|---|
| I. Domain logic lives in RekkertCore | Rules stay out of views and platform adapters | **Pass.** Fixes land in `RekkertCore`/`RekkertSync`. | **Pass.** `KeptCode`, `LinkRecord`, `ParticipantState` and the new wire kinds are pure `RekkertCore`. The Bluetooth state machine moves out of the CoreBluetooth adapter into a platform-free core (D-16). Views only render status and forward requests. |
| II. Deterministic, convergent state (NON-NEGOTIABLE) | Every device that has seen the same events computes the same state; reconciliation is monotonic | **Pass.** The defects are delivery defects, not merge defects. | **Pass, with care.** D-5 changes *what is sent and when the outbox forgets*, never how events merge. Catch-up is by vector difference, so nothing is lost. D-12 changes which session a watch *adopts*; the session it gives up is filed, not dropped. Both get convergence tests in the multi-device harness, including seven guests and an app ended mid-match. The reducer and the wire's event format are unchanged. |
| III. Test the engine, test-first | Device-free tests pin every rule; bug fixes start with a failing test | **Pass.** | **Pass.** Every root cause (RC-1..RC-5, RC-7, RW-2, RW-4) is first a failing test under `SimulatedRadio` (D-16, SC-005). That extraction is what makes the Bluetooth logic testable at all. |
| IV. verify.sh is the gate | Green means `scripts/verify.sh`; silent runtime invariants are asserted | **Pass.** | **Pass.** No new Info.plist keys or entitlements are needed: Keychain, restoration and local notifications use what is declared already. If implementation finds one is needed, `verify.sh` gains an assertion for it in the same change. The new tests run inside `swift test`, which `verify.sh` already calls. |
| V. Local-first, private by construction | No servers; nothing leaves the devices at the court unasked | **Pass.** | **Pass.** The code is kept this-device-only, never in a backup or iCloud Keychain, for at most 12 hours, and only on devices that have been on the match (D-1). The sharing record holds no names, scores or codes, and leaves the owner's devices only through their own Share button (D-11). The QR image is drawn on the phone. Nothing contacts a server. |
