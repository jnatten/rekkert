# Implementation Plan: Rekkert on Apple Watch SE (1st generation)

**Branch**: `003-apple-watch-se-support` | **Date**: 2026-11-04 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-apple-watch-se-support/spec.md`

## Summary

The SE (1st generation) cannot update past watchOS 10.6.1, and Rekkert's watch app requires
watchOS 26. A trial build with the floor lowered to watchOS 10 found the gap to be four
places in the watch app and `Shared/`. The engine (`RekkertCore`, `RekkertSync`) builds
unchanged, and once those four places were stubbed the iPhone app built and embedded the
watch app ([research.md](research.md) R-3).

The approach:

- **Lower the floor.** Set `RekkertWatch` and the `RekkertKit` package to watchOS 10.0, with
  iOS and macOS staying at 26 (D-1). Amend the constitution's platform line to match (D-10).
- **Effort ratings stay in Rekkert on watchOS 10.** Rekkert's own history already gets the
  rating over the existing `.rated` signal (R-4). The watch skips the Apple Health write, and
  the permission request for it, unless it is on watchOS 11 or later (D-2).
- **The disclosure learns the difference.** `HealthDisclosure` in `RekkertCore` gains an
  `effortInAppleHealth` input, and the watch passes in what its Apple Health can hold, so the
  permission request and the words keep coming from one tested place (D-3). The phone's page
  gets one fixed sentence that is true for every pairing (D-4).
- **Two drop-in equivalents.**
  - The round alarm keeps `Observations` where it exists. Below watchOS 26 it follows the
    store with `withObservationTracking` instead (D-5).
  - The workout recorder's `Mutex` becomes an `OSAllocatedUnfairLock` (D-6).
- **Guard the floor.** `verify.sh` asserts that the built watch app's minimum is watchOS 10.0.
  The compiler then rejects any newer API used without a fallback (D-7).
- **Prove it on the wrist.** Test on a real SE (1st generation), following
  [quickstart.md](quickstart.md). Regression-test current watches on the watchOS 26 simulator
  (D-8).
- **Update the docs.** The README states the requirements. The privacy page and review notes
  stop promising an effort rating in Apple Health from every watch (D-9).

Nothing on the wire changes (D-12).

## Technical Context

**Language/Version**: Swift 6.2 tools, Swift 6 language mode. Default isolation is
`MainActor` in the apps and in `RekkertSync`; `RekkertCore` is nonisolated.

**Primary Dependencies**: Apple frameworks only. Already in use:

- SwiftUI, WatchKit, HealthKit, WatchConnectivity, CoreBluetooth and UserNotifications;
- `Observation`, now also `withObservationTracking` for the fallback;
- `os` (`OSAllocatedUnfairLock`), which replaces `Synchronization` in the watch app.

**Storage**: Unchanged. The effort rating stays in `WorkoutRecord.effort` in Rekkert's own
store. Apple Health holds a copy only on watchOS 11 and later.

**Testing**:

- Swift Testing in `RekkertCoreTests` covers the disclosure rule and wording (macOS, no
  device).
- `scripts/verify.sh` covers builds, embedding and the new floor assertion.
- The watchOS 26 simulator covers regression on current watches.
- A real SE (1st generation) on watchOS 10 covers the success criteria.

**Target Platform**: iPhone and iPad on iOS 26 (unchanged). Apple Watch on **watchOS 10.0
and later** (was 26). macOS 26 for package tests (unchanged).

**Project Type**: Mobile app with an iPhone app, an embedded watchOS app and a widget
extension, all generated by Tuist, plus a local Swift package (`RekkertKit`).

**Performance Goals**: These come from the spec and are measured on the SE (1st generation):

- the tap shows on the wrist within 0.5 s, including after 20 rounds (SC-003);
- the point reaches the phone within 2 s (SC-002);
- the time-up buzz comes within 2 s of a current watch (SC-005);
- at least 40% battery is left after a 2-hour session with a workout (SC-006).

**Constraints**:

- Players on watchOS 26 and later see no change (FR-010).
- No change to the wire format, the reducer, draws or schedules (Principle II).
- Every API newer than watchOS 10 sits behind `#available` or `@available` with a
  fallback.

**Scale/Scope**:

- Two manifests (`Project.swift`, `Package.swift`).
- Four source files: `WatchApp/Sources/WorkoutController.swift`, `Shared/HealthTypes.swift`,
  `Shared/RoundAlarmFollower.swift` and `RekkertCore/Health/HealthDisclosure.swift`.
- One small new `Shared/` helper and one test file.
- `scripts/verify.sh`, three documents and the constitution.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

| Principle / constraint | Check | Status |
|---|---|---|
| I. Domain logic lives in RekkertCore | What the watch saves and reads is decided in `HealthDisclosure` (core). The shell only reports whether its Apple Health can hold an effort rating (D-3). The alarm's timing stays in `RoundAlarm`, and the follower only delivers changes (D-5). | PASS |
| II. Deterministic, convergent state | The wire, `WorkoutSignal`, the reducer, version vectors and draws are all untouched (D-12). A rating still travels as `.rated`. The SE (1st generation) runs the same engine. | PASS |
| III. Test the engine, test-first | The `HealthDisclosure` input and the new effort wording get failing tests in `HealthDisclosureTests` first. Lowering the package's watchOS floor does not affect the macOS test run. | PASS |
| IV. verify.sh is the gate | A new assertion fails the gate if the watch app's minimum is anything other than watchOS 10.0 (D-7). | PASS |
| V. Local-first, private by construction | No new data flow. On watchOS 10 one less thing goes to Apple Health, and the permission request asks for less. | PASS |
| Platforms: "iOS, watchOS, and macOS 26" | This feature changes the watchOS floor to 10. | **AMEND** (D-10): MINOR bump to 1.1.0, as the first task |
| Swift 6 / isolation | `OSAllocatedUnfairLock` is `Sendable`. The tracking fallback runs on `MainActor`, like the follower. | PASS |
| Project generation | The floors change in `Project.swift` and `Package.swift`, not in generated files. | PASS |
| Dependencies | Apple frameworks only. | PASS |

Gate result: **pass, subject to the constitution amendment** (see Complexity Tracking).

**Post-design re-check** (after the data model, contracts and quickstart): unchanged.

- The data model adds no persisted field and no wire field.
- The contracts limit the Apple Health change to the watch's request and one sentence of
  wording.
- The quickstart verifies FR-003 convergence on real devices.

**Structure Decision**: This uses the existing layout: Tuist app targets, `Shared/` for code
both apps compile, and `RekkertKit` for the engine. The one new file is a small helper in
`Shared/`, next to the follower that uses it. The iPhone target compiles it too, but iOS 26
always takes the `Observations` branch, so the helper only runs on watchOS below 26.

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| The constitution's platform line ("watchOS … 26") no longer holds | The SE (1st generation), Series 4 and Series 5 cannot run anything past watchOS 10.6.1. Supporting them *is* lowering the floor (R-1). | Keeping watchOS 26 means not doing the feature. The amendment (D-10) makes the new floor, and the fallback rule that goes with it, part of the constitution rather than an exception to it. |
| Two code paths in `RoundAlarmFollower` | `Observations` does not exist below watchOS 26, and replacing it everywhere would change behaviour on current devices (FR-010). | A single fallback path everywhere gives up `Observations`' coalescing on every current device. Polling costs battery and latency (D-5). |
